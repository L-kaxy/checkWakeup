# 解锁与时段 / CheckWakeup

轻量 Android 应用。仅记录和展示，不拦截、不限用、不读取页面内容。可选的后台上报默认关闭。

## 当前范围

- 统计日为本地时区当天 **06:00 至次日 06:00**，不是零点换日。
- 今日解锁总数、全部解锁时间、最近一次解锁时间。
- 选择当前用户下一个可启动的已安装 App。
- 配置最多 12 个时间段，默认 09:00–11:00、15:00–17:00、20:00–22:00。
- 在每个时间段内，目标 App **连续前台至少 10 秒**即完成，不限页面。
- 同 App 的页面切换不重计；切到别的 App、熄屏、锁屏会结束本次计时。
- 显示待开始、待完成、已完成及达标时间、已结束未达标。
- 可展开的锁屏通知和应用内看板。
- 默认保留原版通知；可用独立开关试验 Android Live Updates，查看系统实际提升标志。
- 独立的加密上报开关，默认关闭；共用上报地址，自定义手机名称，随机设备码区分手机。
- 无账号、无第三方运行库、无辅助功能服务、无悬浮窗；仅可选上报使用联网权限。
- **桌面小组件不在首版内。**

## 安装与试用

1. 安装 `dist/checkwakeup-0.3.2-release.apk`，支持 Android 9 / API 28 及以上。
2. 打开应用，进入“使用记录权限”，允许访问。
3. 按需允许通知，并在系统设置中允许锁屏显示通知内容。
4. 选择目标 App，编辑所需时间段，点击“开始监控”。
5. 如果系统限制后台运行，按机型开启自启动、后台运行或取消电池限制。

这是本地测试签名，不是商店发布包。保留 `.signing/local-test.p12`，后续版本使用同一签名才能覆盖安装并保留数据。该测试密钥的密码为公开的 `android`，不能用于正式发布。

## 可选后台上报（0.3.1：变化上报 + 15 分钟心跳）

1. 使用原签名覆盖安装，**不要卸载**；原监控、时段和通知模式保留，上报开关首次升级为关闭。
2. “数据上报”预填构建时注入的共用地址（原本机配置已迁移保留）。
   填写方便辨认的名称，打开“启用加密上报”并确认。填写网站根地址也会自动补全上报路径。
3. 观察“最近成功”及待传天数，在后台查看同名设备。改名不会改变随机设备码；不读取 IMEI、序列号、Android ID 等硬件/系统标识。卸载重装后设备码变化。
4. 开关关闭会取消尚未开始的网络请求/重试、断开正在使用的连接并清除本机待传快照；本地统计、监控和通知照常工作。已经发出的请求可能已被服务器接收，不能撤回；后台已收数据不会被删除。

实现与边界：

- 仅在**解锁记录、首次达标时间、时段状态、目标 App/时段配置、设备名称、监控状态、时区/统计日或数据可用性发生变化**时生成完整日快照立即上报；正常同步时间、计算时间和连续时长的每秒增长不算上报触发条件。
- 没有上述变化时，距离上次生成快照满 **15 分钟**生成一次完整快照作为心跳，携带最新精确统计、诊断时长和同步时间。任意实际变化上报会重新开始心跳间隔；不把达标时间取整或改成心跳时间。
- 心跳与原统计刷新解耦：不降采样本地事件、不改变 10 秒达标规则、06:00 换日和通知更新逻辑。监控服务运行时，应用看板只读取统计，避免服务和界面各自重复上报。
- 无变化的刷新不改写上报队列和序号、不重复加密联网。触发状态和上次入队时间持久化，进程重启不会重置心跳计时；原先的未确认请求仍按固定业务正文重试。
- 正常监控下解锁时约每 2 秒刷新，锁屏约每 60 秒；不新增上报通知、不申请通知权限、不持有唤醒锁、不额外开启前台服务。
- **监控暂停时，仅打开本页回补/刷新会产生新统计上报**。上报开关本身不会强行启动监控或绕过 Doze、强行停止及厂商后台限制。
- 心跳由正常统计刷新检查，不使用精确闹钟或唤醒锁。系统休眠/强行停止可能延后心跳，下次执行机会再发送，不为凑足 15 分钟而唤醒手机。
- 使用独立 SQLite 持久化队列。同一天/时区仅保存最新完整快照，单连接串行发送；离线不会累积每两秒一条的无限请求。最多保留最近 31 个统计日/时区快照，容量外未传快照会过期并在状态中提示。
- 一个已开始的请求固定 `report_id`、`sequence`、业务正文；进程重启重试不修改原请求。后续刷新合并到待传日快照。回执只确认本次对应的版本，不能清掉同时产生的新版本。
- 06:00 后保留上一日数据，用上一日自己的目标 App、时段和时区进行收尾；允许系统事件延迟两分钟再稳定收尾。仅回补系统仍可查询的近一日，不用今日新配置重算全部旧历史。较久未运行的旧快照保留实际观察时刻，不伪造完整日记录。
- 网络异常、408/425/429/5xx 指数退避重试（基础 5 秒到 5 分钟，加少量随机抖动），遵守可解析的 `Retry-After`（安全上限一天）。400/409/413/415/422 等配置/协议错误停止自动重试并显示状态，检查后点“重试上报”使用最新快照。
- 连接超时 8 秒、读取超时 10 秒，另设 30 秒连接断开看门狗；不跟随重定向，回执限制 64 KiB，校验报告 ID、数量、索引、版本和结果类型。
- 更换地址会取消旧地址请求并清除其待传队列，不自动把旧地址的历史发送给新地址；新地址从当前统计日开始。只修改名称会保留待传日快照，并使用新请求/名称发送。
- 缺权限/查询失败时携带 `stale`/`unavailable` 和最后成功同步时刻，不能把未知数据当成已成功读取的零次。
- 0.3.0 → 0.3.1 只为本机上报库增加变化指纹列，保留设备码、单调序号、旧日快照、未确认请求及上报开关，不需要卸载或清数据。
- **后台展示兼容**：本地后端 `../checkWakeup_backend` 已应用兼容补丁，将“未连接/数据待更新”阈值从 3 分钟改为 20 分钟，适配 15 分钟心跳及 5 分钟宽限。不改 API、加密协议或数据库；线上服务未修改，需重新部署后生效。

`dist/backend-heartbeat-compat.patch` 保留供尚未更新的后台源码使用：先用 `patch --dry-run -p1 < 补丁路径` 检查，再用 `patch -p1 < 补丁路径` 应用。本地后端已经应用，不要重复执行；按原方式重新构建部署即可。

请求参数加密：

- **所有业务字段都在 JWE compact 请求正文内**，`Content-Type: application/jose`，URL 不含设备码、名称或统计参数。
- `RSA-OAEP-256`（显式 SHA-256 与 MGF1-SHA-256）+ `A256GCM`；每次加密重新产生 256 位内容密钥和 96 位 IV，认证标签 128 位。
- RSA-3072 或更长的 **公钥**、`kid` 和默认上报地址由构建配置注入，不再写死在源码中。App“技术信息”可查看当前公钥指纹；本机原配置已迁移到被忽略的 `.config/`。
- 不内置后台密码、私钥或公开测试密钥；不通过 HTTP 自动获取并信任新公钥。更换后台密钥需要更新构建配置并重新发布 APK。公钥打入 APK 后可被提取，并非手机中的秘密。
- 按当前要求支持 HTTP，只加密业务请求正文；**地址、流量特征及响应并非加密或签名保护，不能等同 HTTPS 或请求端身份认证**。若配置 HTTPS，保留系统正常的证书和主机名校验，不做信任全部证书的处理。
- 关闭时不发送业务数据。开启时会发送解锁明细、目标 App 包名/名称、时段状态、监控状态、随机设备码、设备名称、App/系统版本及设备时区，不上传系统全部使用事件或 App 内页面内容。

## 通知模式切换（0.2.0）

- 在“锁屏通知模式”打开或关闭 **Live Updates 实验模式**，默认为关闭；升级不会自动开启。开关保存到本地，暂停/恢复监控不清空此设置。
- **关闭**：完全沿用 0.1.0 的摘要（解锁总数、目标 App 完成时段数）和展开详情。
- **打开**：向同一条持续通知加入标准 `android.requestPromotedOngoing` 请求，并继续使用系统 `BigTextStyle`。没有自定义 RemoteViews、私有接口或小米 SDK。
- 实验模式未展开摘要优先展示解锁次数、最近一次解锁时间、各时段状态：`✓` 完成、`○` 待开始、`…` 待完成、`×` 已结束未达标。小屏/大字体/较多时段仍可能截断。
- 开关只影响显示请求，**不改变 10 秒口径、时段配置、数据保留或 06:00 换日**。
- 本版先验证设备是否接纳 Live Updates，**没有加入每小时自动取消/重发**；不能通过频繁换通知 ID 保证大卡片。
- “Live Updates 系统设置”尝试进入公开的应用通知提升设置；系统不提供时退回普通通知设置。
- 诊断分开显示：公开接口是否存在、系统是否允许提升、活动通知是否含请求、格式是否符合条件、系统实际提升标志。前三项成功不等于最后一项成功；标志成功也不保证厂商锁屏外观完全相同。
- 手动移除实验通知会关闭实验开关；监控仍可继续，后续回到原版普通通知，不自动重新请求提升。带版本代号的删除 PendingIntent 避免旧通知的延迟删除误关新一次实验。
- 官方 API 在不同 Android 16 小版本中的可用性不完全相同，因此按实际公开字段/方法探测，不单凭版本名推断。探测失败显示“无法判断”，不当作成功或确定不支持。
- 本地仍使用 SDK 35 编译：请求使用官方公开 extras 字符串，新版诊断接口仅通过公开反射探测；旧系统可忽略未知 extras。**真实接纳能力必须由手机验证，未在本机运行 Android。**

红米 Note 15 Pro+ / HyperOS 3.0.317.0 / Android 16 的建议验收：

1. 使用原签名覆盖安装，不要卸载，以保留本地数据。开始监控后先确认开关关闭，通知与旧版一致。
2. 打开实验开关，等待 2–3 秒，查看“系统实际提升标志”，再查看锁屏和通知栏。

## 统计细节

- 窗口为 `[开始时间, 结束时间)`，只计算与窗口重叠的前台时长。
- 08:59 已经打开，并持续前台到 09:00:10，可以完成 09:00–11:00。
- 前台 6 秒、后台、再前台 5 秒，**不累计**。
- Android 会先暂停旧 Activity 再恢复新 Activity。因此仅在 **500ms 内同包页面切换，且中间没有其他 App 进入前台**时连接会话。这是生命周期转换容差，不是后台累积。
- 窗口结束前恰好达到 10 秒（例如 10:59:50 至 11:00:00）算完成。
- 23:00–01:00 支持跨午夜；01:00–02:00 归属上一个 06:00 开始的统计日。
- 时间段不能跨过 06:00 换日；例如 05:00–07:00 请拆成 05:00–06:00、06:00–07:00。
- 完成时间是首次达到连续 10 秒的时间，不是 App 打开时间。
- 更换目标 App 或修改窗口后，会按新设置重新计算当前统计日，不沿用旧目标的完成状态。
- “解锁”采用系统 `KEYGUARD_HIDDEN` 事件；只亮屏、通知唤醒和 AOD 不直接算解锁。未设置锁屏、可信解锁和人脸识别行为需要在目标机型验证。
- 原始系统事件只在本机 SQLite 中保留 30 天；可选上传的是日统计快照，不是原始事件流，不读取 App 内业务行为。

## 数据与后台限制

这是 `UsageStatsManager.queryEvents()` 的系统记录回放，并非修改系统或跟踪进程：

- 屏幕可交互且已解锁时每 2 秒同步；锁屏/熄屏后降为每 60 秒。没有持有唤醒锁。
- 使用前台服务维持用户主动开启的监控，声明 Android 14+ 的 `specialUse` 类型。
- 查询回看 60 秒处理晚到事件；每 15 分钟以及打开本页、屏幕状态变更时重新回补当前日及前一天的数据。
- 对尚未结束的前台会话保守延迟 1.5 秒判断；再加轮询与系统事件延迟，通知不保证恰好在第 10 秒出现。
- 系统可能晚到、乱序、遗漏或清理使用事件；缺少数据不等于确定没使用过。首次安装前的当日记录尽力回补，不保证完整。
- 重启后首次解锁前不能读取凭据加密的系统使用记录；首次解锁后再恢复。
- 系统杀进程后的恢复和历史回补是尽力而为，不绕过用户强行停止。
- 06:00 是**计算边界**。Doze 或厂商策略可能延迟通知刷新；下次获得执行机会会正确切换到新统计日，不保证休眠中 06:00 准点刷新。
- 分屏、画中画、工作资料、应用双开、私密空间、系统浮层可能有不同的前后台语义，首版不保证准确。
- 暂停监控会移除持续通知；之后打开本页仍会回补系统记录，不代表清空或拒绝统计暂停期间的使用。

## 最小构建

默认不需要 Android Studio、Gradle、Kotlin、模拟器、NDK、CMake、adb 或第三方依赖。

构建脚本使用 JDK 17 + SDK Platform 35 + Build Tools 35.0.0：

```sh
bash scripts/bootstrap-toolchain.sh
# 首次准备 .config/build.json 和 .config/signing.json（本机已经迁移保留）。
# 模板见 config/；密钥和 GitHub 配置步骤见 GITHUB_RELEASE.md。
python3 scripts/check-static.py
bash scripts/test-core.sh
bash scripts/test-upload.sh  # 使用仓库内公开测试夹具，不需要后端目录或生产配置
python3 -m unittest discover -s tests -p 'test_*.py' -v
bash scripts/build.sh
```

`bootstrap-toolchain.sh` 为 macOS Apple Silicon 下载工具，校验 JDK 与 SDK 存档摘要，只解压到项目的 `.toolchain/`，不修改系统环境。它从 Google 官方 SDK 仓库元数据解析两个指定包。SDK 使用适用的 Android SDK 许可。已有工具链可设置 `JAVA_HOME`、`ANDROID_HOME` 后跳过下载；SDK 中需有相同版本的 Platform 和 Build Tools。

打包流程：

```text
AAPT2 编译/链接资源 → javac → D8 → zipalign → apksigner → 签名/对齐验证
```

输出：

- `dist/checkwakeup-0.3.2-release.apk`
- `dist/checkwakeup-0.3.2-release.apk.sha256`
- `dist/build-info.json`

源码同时保留标准 AGP 项目配置，便于未来导入 Android Studio；它不是默认构建路径，当前没有下载 Gradle Wrapper。

## 建议的有限真机验收

1. 连续解锁 3 次，核对总数与每次时间；只点亮锁屏不应增加。
2. 把一个时段设为当前时间附近，目标 App 前台停留 12–15 秒后查看是否完成。
3. 测试“6 秒 → 回桌面 → 5 秒”，应未完成；“页面 A 6 秒 → 页面 B 6 秒”应完成。
4. 前台 6 秒后锁屏 20 秒，再解锁使用 5 秒，不应把两次拼成 10 秒。
5. 核对锁屏通知的展开内容、最近解锁、三个时段状态。
6. 验证重启、系统回收、手动暂停/恢复，以及凌晨 06:00 后的归属。
7. 上报关闭时使用本地统计；启用后确认后台出现当前手机、当天解锁明细和各时段状态。无解锁、状态或配置等变化时，接收/同步时刻应约每 15 分钟更新，而不是每 2 秒更新。
8. 断网一段时间再联网，观察重试并确认同日只有一份最新快照；后台数据应与 App 对齐。
9. 改名后确认仍是同一设备；不同手机同名仍应分开。关闭上报后确认后台接收时刻停止变化（已在途请求可能完成），本地计数和通知继续更新。
10. 跨 06:00 检查昨日历史与今日重置，确认旧日达标时间没有被新日清空；更换目标 App/时段仅影响当前统计日重算。
11. 前台停留达到 10 秒时应及时更新完成状态，不能等 15 分钟心跳才完成；连续保持在前台时，诊断时长逐秒增长不应反复发起上传。

不要仅为测试在主力手机上来回改系统时间：系统历史会跟随墙上时钟，可能混淆真实数据；时间边界已经通过确定性的 JVM 测试覆盖。
