> **只记录，不干预。**
> CheckWakeup 不是防沉迷或应用拦截工具：不限制使用、不读取页面内容，也不需要辅助功能或悬浮窗权限。
> 不连接后台也能使用完整的本地统计与通知功能。

## 项目能做什么

你可能只想知道两件事：

**今天解锁了几次？某个 App 是否在约定的时间段里，真正打开使用过？**

CheckWakeup 把它们放在同一个看板里，并支持在锁屏通知中查看。

| 功能 | 说明 |
| :--- | :--- |
| 🔓 **解锁记录** | 今日解锁总数、最近一次解锁时间，以及当天全部解锁时间。 |
| ⏱ **App 时段检查** | 选择一个已安装的 App，在每个时段内连续前台使用至少 **10 秒**，即记为完成。 |
| 🌅 **06:00 换日** | 按本地时区，以当天 06:00 至次日 06:00 为一个统计日，凌晨使用不会在零点被分开。 |
| 🔔 **锁屏通知** | 普通持续通知展示统计；另提供可独立切换的 **Live Updates 实验模式**。 |
| ☁️ **可选加密上报** | 开关默认关闭；启用后数据变化时上报，无变化时每 **15 分钟**心跳。 |
| 📱 **多设备查看** | 配合后台按设备查看每日历史；设备码区分手机，名称便于辨认。 |

默认检查三个时段，也可自行编辑，最多配置 **12 个**：

```text
09:00—11:00       15:00—17:00       20:00—22:00
```

## 首次使用

### 1. 安装 APK

从 [Releases](https://github.com/L-kaxy/checkWakeup/releases) 下载 APK，按手机提示完成安装。支持 **Android 9 / API 28 及以上**。

如果暂时没有 Release，可进入 [Actions](https://github.com/L-kaxy/checkWakeup/actions/workflows/android-release.yml)，打开一次成功的签名构建，在 **Artifacts** 下载并解压 APK。源码 ZIP 不是安装包。

> [!IMPORTANT]
> **升级时直接覆盖安装，不要先卸载。**
> 官方工作流沿用原签名；卸载会丢失本地数据与设置，重新安装后的设备码也会变化。
> 自行构建时若换用了另一张签名证书，将无法按原方式覆盖升级。

### 2. 配置权限与后台运行

| 设置 | 用途与注意事项 |
| :--- | :--- |
| **使用记录权限** | 统计所必需。点击应用内「使用记录权限」，在系统中允许访问，再返回应用。 |
| **通知与锁屏显示** | 用于展示持续统计通知。点击「通知设置」，并按需允许锁屏显示通知内容。 |
| **后台与电池设置** | 用于改善长时间监控的存活情况。按机型允许自启动、后台运行，或适当放宽电池限制。 |

**红米 / 小米 / HyperOS 用户：** 可从应用内「后台与电池设置」进入相关设置；实际入口和选项以本机系统为准。允许后台运行不等于系统永远不会终止应用。

### 3. 选择目标与时段

1. 点击「选择一个已安装 App」，选择要检查的应用；列表显示当前用户可启动的应用。
2. 在「时段检查」中编辑、添加或删除时间段。
3. 点击「开始监控」，确认页面没有权限或读取错误提示。

建议先保持 **Live Updates 实验模式关闭、加密上报关闭**，确认本地统计正常后，再按需启用。

### 4. 做一次小验证

- [ ] 锁屏后重新解锁，检查计数与最近解锁时间是否更新。
- [ ] 在当前检查时段内，让目标 App 连续前台显示超过 10 秒。
- [ ] 返回 CheckWakeup，确认对应时段已完成，并显示首次达标时间。
- [ ] 锁屏查看通知；普通模式需要展开才能查看完整详情。

首次安装前的当日记录会尽力回补，但取决于系统保留的数据，**不保证完整**。不要为了测试而来回修改主力手机的系统时间。

## 统计口径

### 什么才算「使用过」？

不是仅仅拉起进程，也不是在后台运行。目标 App 必须在对应时段内 **连续前台至少 10 秒**，任意页面均可。

| 使用情况 | 是否达标 |
| :--- | :--- |
| 同一个 App 连续前台 10 秒 | ✅ 达标 |
| App 内正常切换页面，保持连续使用 | ✅ 不因换页重新计时；短暂生命周期切换有容差 |
| 前台 6 秒 → 切到别的 App → 前台 5 秒 | ❌ 不累计为 11 秒 |
| 仅后台运行，或处于锁屏状态 | ❌ 不计为连续前台使用 |
| 08:59 已打开，持续使用到 09:00:10 | ✅ 可完成 09:00 开始的时段 |

- 时段旁的时间是 **第一次达到连续 10 秒的时刻**，不是首次打开时间，也不是最后一次使用时间。
- 多次使用不会把已记录的首次达标时间改成更晚的时间。
- 同 App 页面切换允许 **500ms 内、且中间没有其他 App 进入前台**的生命周期转换容差，并非允许累计后台时长。
- 「已结束未达标」表示**没有观察到符合规则的连续使用**，不等于这个时段里从未打开过。

### 「今天」为什么不是零点开始？

统计日按手机本地时区计算：**当天 06:00 → 次日 06:00**。例如凌晨 01:00 的记录归入前一个 06:00 开始的统计日。

支持 `23:00—01:00` 这样的跨午夜时段，但时段不能跨越 06:00 换日边界。`05:00—07:00` 请拆成 `05:00—06:00` 与 `06:00—07:00`。

> [!NOTE]
> 切换目标 App 或修改时段，会按新设置重新计算当前统计日。
> 06:00 是统计边界，不是精确唤醒闹钟；系统休眠时，界面和通知可能在下次运行机会才刷新。

## 锁屏通知

| 模式 | 显示方式 |
| :--- | :--- |
| **普通模式 · 默认** | 收起时显示解锁次数与 App 完成时段数；展开后查看最近解锁时间、各时段状态及达标时间。 |
| **Live Updates · 实验** | 尝试在摘要中直接显示最近解锁时间和各时段状态，并请求系统提升展示；可随时关闭，恢复普通模式。 |

**实验开关不是“大卡片保证”。** 系统版本、厂商实现、通知权限、字体与屏幕空间都可能影响展示；请求成功也不代表一定会得到类似 iOS 实时活动的外观。

<details>
<summary><strong>通知显示不完整、没有大卡片，或实验模式异常？</strong></summary>

- 先确认系统允许此应用通知，并允许锁屏显示内容。
- 普通模式的完整信息位于展开视图，收起时只显示摘要。
- 实验模式可查看应用内诊断，区分「已请求提升」与「系统实际提升」。
- 小屏、大字体或时段较多时，摘要仍可能被截断。
- 手动移除实验通知后，实验开关会关闭；监控仍继续，后续恢复普通通知。
- 若出现异常亮屏或显示行为，可先关闭实验模式对比，并检查本机通知亮屏设置。

当前没有每小时自动取消、重发通知的功能，也**没有桌面小组件**。

</details>

## 可选后台上报

**不需要后台？保持关闭即可。** 本地统计、10 秒判定和通知不受影响。

需要集中查看多台手机时：

1. 在「数据上报」中确认后台地址，填写或修改便于辨认的名称。
2. 打开「启用加密上报」，阅读并确认提示。
3. 查看「最近成功」与待传状态，再到配套后台按设备查看每日历史。

| 行为 | 说明 |
| :--- | :--- |
| 数据变化 | 解锁、首次达标、时段状态、配置或数据质量变化时，生成完整快照上报。 |
| 数据无变化 | 每 15 分钟生成一次完整快照心跳，不改变本地统计精度。 |
| 断网 | 在本机持久化、合并待传日快照，恢复后按重试规则发送。 |
| 关闭上报 | 停止后续上报并清理待传数据；已发出的请求无法撤回，后台已收到的记录不会被删除。 |

多台手机可以使用同一上报地址，**随机安装设备码用于区分设备，名称仅用于展示**；改名不会变成新设备。

> [!IMPORTANT]
> 请只对你信任的后台启用上报。
> **后台地址必须与此 APK 构建时注入的公钥、kid 配套**；只更换 URL，并不能自动适配任意新服务器。
> 休眠、强行停止或暂停监控可能延后心跳，不保证严格每 15 分钟送达。

## 数据与隐私

- **默认本地保存。** 上报开关首次默认关闭；原始系统事件仅在本机保留，按 30 天清理。
- **只处理统计所需信息。** 不读取页面文字、聊天内容或截图，不采集 IMEI、序列号、Android ID。
- **启用上报后**，发送解锁时间、目标 App 包名与名称、时段状态、设备名称与随机设备码、监控状态、App / 系统版本、时区及数据质量信息；不上传系统全部原始使用事件。
- **请求正文加密。** 业务字段采用 JWE：`RSA-OAEP-256 + A256GCM`；APK 仅包含公钥，不包含后台解密私钥。
- **锁屏也有隐私边界。** 统计信息可能被身边的人看到，请自行设置锁屏内容可见性。

> [!WARNING]
> 请求参数加密 **不等同于 HTTPS，也不等同于设备身份认证**。
> 使用 HTTP 时，地址、流量特征、响应和后台管理页面并不因此获得传输保密保护。
> 公钥可以从 APK 提取，它不是需要藏在手机里的私钥。

## 常见问题

<details>
<summary><strong>为什么计数没变，或时段没有立刻完成？</strong></summary>

先检查使用记录权限、监控状态和页面错误提示。数据来自 Android 系统使用事件，可能延迟、缺失或被清理，不是实时读取其他 App 的页面。

正常监控时，解锁状态约每 2 秒刷新，锁屏后约每 60 秒刷新；正在进行的前台会话还会保守等待晚到事件，因此不能保证恰好在第 10 秒更新。

**数据缺失不等于没有解锁或没有使用。**

</details>

<details>
<summary><strong>只是亮屏，为什么不一定计入解锁？</strong></summary>

统计基于系统的锁屏解除事件。通知唤醒、AOD 或单纯点亮屏幕不直接视作解锁。
免锁屏、可信解锁、人脸识别等行为的实际事件表现，需要在具体手机上验证。

</details>

<details>
<summary><strong>一直在后台运行，会很耗电吗？</strong></summary>

应用使用前台服务维持监控，锁屏后降低轮询频率；通知仅在可见内容变化时更新，上报也只在变化或心跳到期时生成。没有为凑准心跳而增加唤醒锁或精确闹钟。

但这不代表零耗电。实际耗电取决于机型、使用频率、网络和后台限制，项目不承诺未经实测的续航数字。

</details>

<details>
<summary><strong>退出页面、重启手机后，还能继续统计吗？</strong></summary>

开启监控后，离开页面由前台服务继续工作；系统终止后的恢复与历史回补是尽力而为，不绕过用户强行停止或厂商限制。

手机重启后需要先解锁一次，才能读取相关系统记录。暂停监控会移除持续通知；之后打开应用仍可能回补系统保留的记录，并不代表此前的数据已被清空。

</details>

<details>
<summary><strong>分屏、画中画、应用双开能准确判断吗？</strong></summary>

这些场景以及工作资料、私密空间、系统浮层可能有不同的前后台语义，目前不保证准确。不要把本应用用于需要严格证明或审计的场景。

</details>

<details>
<summary><strong>Actions 成功了，为什么 Releases 还是空的？</strong></summary>

当前工作流将「构建」与「正式发布」区分开：

- **Pull Request**：无 Secrets 的检查，不签名、不发布。
- **推送 main / master，或手动选择分支运行**：构建签名 APK，上传到该次运行的 Artifacts。
- **推送匹配版本的 v* tag**：构建后自动创建 Release，并附上 APK、校验值与构建信息。

版本 tag 必须与 `version.json` 对应。具体步骤见 [GitHub 发布指南](GITHUB_RELEASE.md)。

</details>

## 开发与发布

**Java 17 · 原生 Android UI · SQLite · 无第三方运行库**

默认使用轻量构建链，不要求安装 Android Studio、Gradle 或模拟器：

```text
构建配置注入 → AAPT2 → javac → D8 → zipalign → apksigner
```

准备 JDK 17、Android Platform 35 / Build Tools 35.0.0，以及本机构建与原签名配置后：

```sh
python3 scripts/check-static.py
bash scripts/test-core.sh
bash scripts/test-upload.sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
bash scripts/build.sh
```

公钥、kid、默认上报地址由构建配置注入；签名证书指纹固定校验，**缺配置或签名不匹配就停止构建，不自动生成新证书**。
